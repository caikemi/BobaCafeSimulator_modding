# 带 Pak Mod 的游戏版本声明

[返回中文首页](../../README.md) | [English](../en/15-pak-game-version.md) | [PAK 打包教程](../../Model_PAK_Packaging_ZH.md)

此规则适用于包含 2026-11-06 加载检查更新的游戏构建。当前主工程 `ProjectVersion` 为 `2.17`；游戏版本显示相同不代表旧构建已经包含此检查。

## 作者必须声明什么

只要 Mod 目录任意层级存在 `.pak` 文件，真实 Lua 入口的首条有效语句必须声明经过适配验证的游戏版本：

```lua
local game_version = "2.17"

local M = {}
function M.OnLoad(Context)
    return true
end
return M
```

- 有 `mod.json` 时，写在 `entry` 实际选择的文件中，例如 `v3.lua`；写进未执行的 `main.lua` 不算。
- 无 `mod.json` 时，旧加载器按 `LuaMain.lua` → `main.lua` → `init.lua` 选择第一个存在的入口。
- 可以在声明前放空行、UTF-8 BOM、普通注释或 Lua 长注释；声明必须是第一条有效语句，独占一行。支持单/双引号、可选 `local`、行尾分号和行尾普通注释。
- 必须是字符串字面量，不接受运行时计算、函数内赋值、其他字段名，或只在注释/字符串中出现的版本。入口文本上限为 1 MiB。
- 按完整字符串与当前游戏 `ProjectVersion` 精确匹配，不接受通配符或版本范围。`2.17`、`2.17.0` 和 `v2.17` 是不同声明。
- Mod 自身的 `version` 和 `apiVersion` 各有用途，不能替代 `game_version`。
- 纯 Lua Mod 没有自带 Pak 时不要求此声明。PNG、JSON、ShaderArchive 文件本身不会被当作 Pak。

## 宿主怎样检查

宿主递归扫描磁盘上的 Mod 目录，扩展名比较不区分大小写；根目录和子目录中的 `.pak` / `.PAK` 都会触发要求。它不会为了读取声明而执行 Lua、载入 DLL、加载资产或挂载 Pak。

首次进入主界面时，现有 Mod 错误读取流程预检真实启用列表，一次列出全部未通过的 Mod 名称、稳定 ID、可识别的工坊编号和失败原因。读取后清除，同一 GameInstance 的首次菜单预检不会重复提示。玩家再次开始游戏时仍重新检查；实际宿主 Pak 挂载入口也重新检查。

缺失声明或版本不匹配会阻止本次进局；启用状态保持原样，不会自动退订、删除 Mod、替玩家修改声明或静默继续游戏。玩家可在列表取消启用相关 Mod，或等待作者更新。

## 作者更新与验证

不要只把数字改成当前版本来消除提示。请先在目标游戏版本、相同平台与兼容 UE 版本下验证资源依赖、蓝图父类和属性布局，再按需重新 Cook/Pak，确认实际加载和内容注册成功后才更新声明并发布。

声明匹配是作者的兼容性承诺，不是宿主证明资源安全。已知坏 Pak 的大小/内容指纹、已知坏 DLL 的构建标识和现有禁用 Pak 文件名前缀检查仍然生效；修改文件名、Mod 版本或补上声明不能绕过已知坏内容保护。

宿主接口会在挂载前校验；旧版 DLL 若自己下载/挂载目录外资源并绕过宿主接口，单靠目录扫描无法保证拦截。此规则不是原生代码沙箱，也不能把 UE 反序列化崩溃变成可继续运行的 Lua 异常。
